# Documentation follows behavior

- Update relevant documentation when setup, commands, dependencies, environment variables, user-visible behavior, API contracts, or operational constraints change.
- Choose the document that owns the information. Do not rewrite the README for every edit or duplicate contracts across multiple documents.
- Bug fixes can require documentation when documented behavior changes; refactoring alone does not require a README update.
- Verify documented commands and file references against the repository. Label proposals and unverified behavior explicitly.
- Do not include credentials, private payloads, or machine-specific secrets in examples.
