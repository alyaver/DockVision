# Minimal, complete changes

- Inspect the affected implementation, callers, tests, and working-tree status before editing. Present a scope and verification plan proportionate to the task.
- Make the smallest complete change that satisfies the agreed outcome, including necessary tests and documentation.
- Do not bundle unrelated formatting, renaming, refactoring, dependency upgrades, or architecture changes.
- Preserve unrelated tracked and untracked work. Never reset, overwrite, delete, or stage it as cleanup.
- Report adjacent defects separately. Explain a necessary scope expansion before proceeding; ask when it changes the agreed outcome.
- In Plan mode, inspect and propose only; do not edit files or mutate external systems.
- Use noninteractive commands appropriate to the actual shell. Resolve repository paths to absolute paths before tool operations; quote paths containing spaces.
